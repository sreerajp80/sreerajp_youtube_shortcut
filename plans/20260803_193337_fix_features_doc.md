# Fix docs/features.md — close gaps and correct inaccuracies

**Status:** completed

## Files to change

- `docs/features.md` (only file changed)

## What the issue is

`docs/features.md` calls itself "a comprehensive, authoritative breakdown of all features." I checked it
against the real code (all screens, the URL formatter, the share-intent service, the backup service, the
error types, and the Android manifest/Gradle files). Most of the document is accurate and very detailed,
but I found:

1. **Six inaccuracies** — places where the doc states something that does not match the code.
2. **A number of gaps** — real behavior in the code that the doc never mentions.

### Inaccuracies found

1. §5.1 lists a "Title subtitle counter showing total saved shortcuts" as one of the App Bar's controls.
   The App Bar title is just the static text "YT Shortcuts" — the counter badge is in the screen body next
   to "Shortcut Sections", as the doc itself correctly says a few lines later. This is self-contradictory.
2. §5.1 claims "Select All / Select None toggles" both exist. Only "Select all" exists (a popup menu item,
   shown only when not everything is already selected). Clearing selection is done via a separate "Clear
   selection" (X) icon button, not a "Select None" toggle.
3. §5.1 says the single-item quick action tooltip reads "Edit". The real tooltip text is "Edit shortcut".
4. §5.2 and §4 both say validation errors show up as real-time **inline** field errors. In the real code,
   the Add/Edit screen has no `TextFormField`/`validator`/inline error text at all — every validation
   failure is only shown after the user taps Save, via a Snackbar.
5. §2 states production release builds "enforce `--obfuscate` ... and symbol table splitting
   (`--split-debug-info`)" as if the build system guarantees this, in the same sentence as the
   keystore-properties gate (which genuinely is enforced by Gradle). In fact only R8 minification
   (`isMinifyEnabled = true`) is enforced by Gradle; `--obfuscate` and `--split-debug-info` are manual
   `flutter build` CLI flags a developer must remember to pass — there is no build-time check that stops a
   release build if they are omitted.
6. §5.7 undersells the Permissions screen's structure — it implies a single flat "implicit OS features"
   list, but the real screen has two sections ("Explicit Permissions: None" and "Implicit Permissions /
   Declarations" with 5 entries, including a "Launcher visibility" entry the doc never mentions at all).

### Gaps found (real behavior missing from the doc)

- Avatar-initial logic (§1/§5.1) is more nuanced than "2-letter initials": single-word names take the
  first 2 letters of that word; multi-word names take the first letter of the first two words only
  (later words are ignored); a blank name yields "?".
- Add/Edit screen has a footer disclosure line: "The app stores the shortcut locally and does not request
  internet access." — not mentioned in §5.2.
- Shortcut Detail screen shows the literal string "Same as created" for the "Updated" row when a shortcut
  has never been edited, instead of a second timestamp.
- The shared-text URL extractor also strips trailing punctuation (`.,;:!?)]}>`) off an extracted URL —
  §4 describes only the "first http(s):// URL" extraction, not this trimming step.
- The clipboard paste-suggestion banner's host-substring check omits `m.youtube.com/`, even though
  `m.youtube.com` is a supported host for saving a shortcut — so a clipboard link on the mobile-site host
  won't trigger the "Paste" banner. Not documented as a limitation anywhere.
- `ShortcutBackupException` (backup_service.dart) does not extend the shared `AppException` hierarchy that
  the other three exception types do — the doc never mentions this structural inconsistency.
- The Permissions screen's "Launcher visibility" entry and its "Explicit Permissions: None" section are
  not mentioned (see inaccuracy #6 above — same fix covers both).
- The Channel Handles screen has a concrete 5-row table of fallback behavior (currently streaming /
  upcoming / past-only / never live / invalid handle) and a "Good to know" section (no connectivity check;
  how to open the channel page instead of `/live`) — §5.8 only vaguely paraphrases this.
- §4's "Scheme Auto-Prefixing" paragraph describes logic (`_hasExplicitScheme`) that only governs the live
  URL *preview* text, not the actual save-time validation path, which uses a simpler `contains('://')`
  check. The doc presents it as if it's one unified rule.
- A bare handle with a dot (e.g. `some.channel`) does not get the handle-specific error message — it falls
  through to a generic "unsupported link" error. §4 says such input is "rejected" but not which error
  message appears.

## Plan for the fix

Edit `docs/features.md` only, section by section:

1. **§1 (App Overview)**: refine the "Cognitive Accessibility" bullet's avatar-initials claim to describe
   the actual single-word/multi-word/blank-name branching.
2. **§2 (Platform Architecture)**: reword the "Release Binary Hardening" bullet to separate what Gradle
   actually enforces (R8 minify, the keystore gate) from what is a manual CLI-flag responsibility
   (`--obfuscate`, `--split-debug-info`), matching `docs/release_process.md`.
3. **§4 (Link Formats)**: 
   - Clarify that the scheme-auto-prefixing "well-formed scheme token" nuance applies to the live preview
     text only, and that save-time normalization uses a simpler check.
   - Add a note on trailing-punctuation trimming in the shared-text extractor.
   - Add a note that a dotted bare handle falls through to a generic "unsupported link" error rather than
     the handle-specific one.
   - Soften "inline form errors" wording (see §5.2 fix below — same underlying correction).
4. **§5.1 (Home Screen)**:
   - Remove/fix the "Title subtitle counter" bullet from the App Bar list (it's not an app-bar element).
   - Fix "Select All / Select None toggles" to describe what actually exists: a "Select all" popup item
     plus a separate "Clear selection" icon button.
   - Fix the quick-action tooltip text to "Edit shortcut".
   - Add the avatar-initials nuance reference (or point to §1).
5. **§5.2 (Add/Edit Screen)**:
   - Replace "Inline Validation" bullet to say errors are shown via Snackbar after Save is pressed, not
     inline/real-time field errors.
   - Add the footer disclosure line ("stores the shortcut locally and does not request internet access").
   - Add a note that the paste-suggestion banner's host check omits `m.youtube.com/`.
6. **§5.3 (Detail Screen)**: add a note about the "Same as created" literal string for the Updated field.
7. **§5.7 (Permissions Screen)**: describe both sections — "Explicit Permissions: None" and "Implicit
   Permissions / Declarations" (5 entries including "Launcher visibility").
8. **§5.8 (Channel Handles Screen)**: add the 5-row fallback-behavior table summary and the "Good to know"
   notes (no connectivity check; workaround to open channel page instead of `/live`).
9. **§3 or a new note near backup_service**: mention that `ShortcutBackupException` is a separate
   exception type, not part of the shared `AppException` hierarchy used elsewhere.

No code changes — this is a documentation-only fix. After editing, I will proofread the whole file once
more for internal consistency (e.g. the App Bar bullet list numbering) before marking this plan completed.

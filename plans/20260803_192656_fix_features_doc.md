# Fix and complete docs/features.md

**Status:** completed

## What is the issue

`docs/features.md` is meant to be the complete, correct list of every feature in the app. I
checked it against the actual code and found small mistakes and a few missing details.

### Wrong text in the doc (compared to real code)

1. **About screen "project credits"** — the doc says the About screen shows "project credits"
   (line 215). The real screen has no credits section at all, just Author, Version, Build date,
   AI used, and a short Notes card.
2. **Selection counter text** — the doc says the selection bar shows text like `"2 selected"`
   (line 146). The real UI only shows the plain number next to a checkmark icon, no word
   "selected".
3. **Empty search state text** — the doc says `"No matching shortcuts found"` (line 158). The
   real text is `"No matching shortcuts"` (no "found").
4. **Quick action button names** — the doc calls them "View details" and "Copy link" (lines
   153-155). The real tooltips are "Shortcut details" and "Copy URL".
5. **Version/build number display** — the doc implies Version and Build number are shown as two
   separate rows (line 215). The real About screen shows them combined in one row, like
   `1.3.15+37`.

### Missing details (things the code does that the doc never mentions)

6. **Dev build version suffix** — dev-flavor builds add `-dev` to the version name
   (`android/app/build.gradle.kts`), visible on the About screen. Not mentioned in §2.
7. **Section 1 (App Overview) gaps** — the summary at the top undersells four things that are
   fully described later in the doc but never called out as value pillars up top:
   - Backup & Restore is a full two-way (export + import, Merge/Replace) feature, not just a
     "portability" one-liner.
   - Per-shortcut usage stats (launch count, last launched date, "Recently launched"/"Most
     launched" sort modes, Activity card) are a real feature, not just a data field.
   - Theme switching (System/Light/Dark) isn't mentioned in Section 1 at all.
   - The single-item quick actions in multi-select mode (view/edit/copy without leaving
     selection) aren't hinted at in Section 1.

## Files to change

- `docs/features.md` — the only file. Fixing wrong text in §5.6, §5.1, and §2, and adding a few
  sentences to Section 1.

## Plan for the fix

1. In §5.6 (About Screen), remove the "project credits" claim; describe the Notes card and the
   combined `version+buildNumber` display instead. Mention the `-dev` version suffix for dev
   builds.
2. In §5.1 (Home Screen), fix the selection counter text, the empty-state text, and the quick
   action button names to match the real strings.
3. In §2 (Build Flavors), add a line noting the dev flavor's `-dev` version name suffix.
4. In Section 1 (App Overview & Inclusive Value Proposition), add short mentions of:
   - Backup & Restore as a full two-way feature.
   - Per-shortcut usage insights and activity-based sorting.
   - Theme switching (System/Light/Dark).
   - Single-item quick actions during multi-select.

No code changes — this is a documentation-only fix. No plan for touching any `lib/` or `android/`
files.

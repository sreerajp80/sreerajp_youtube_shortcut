# Fix docs/features.md — close gaps and correct inaccuracies

Implements: `plans/20260803_193337_fix_features_doc.md`

## What changed

Edited `docs/features.md` only. No app code was touched.

1. **§1 (App Overview)** — described the real avatar-initials logic (single-word vs. multi-word vs.
   blank-name branching), instead of a flat "2-letter initials" claim.
2. **§2 (Platform Architecture)** — corrected the "Release Binary Hardening" bullet: only R8 minify is
   actually enforced by Gradle; `--obfuscate` and `--split-debug-info` are manual CLI flags, not a
   build-time gate like the keystore-properties check.
3. **§3 (Domain Model)** — added an "Error Types" note explaining that `ShortcutBackupException` does not
   share the `AppException` hierarchy used by the other three exception types.
4. **§4 (Link Formats)** — clarified that the "well-formed scheme token" nuance only applies to the live
   URL preview, not save-time normalization; added a note on trailing-punctuation trimming in the
   shared-text URL extractor; added a note on what error message a dotted bare handle actually gets; and
   softened the "inline form errors" wording to match the real Snackbar-based flow.
5. **§5.1 (Home Screen)** — removed the phantom "Title subtitle counter" app-bar bullet (it contradicted
   the doc's own later text placing the counter in the screen body); replaced the false "Select All /
   Select None toggles" claim with what really exists (a "Select all" popup item plus a separate "Clear
   selection" icon button); fixed the quick-action tooltip text from "Edit" to "Edit shortcut".
6. **§5.2 (Add/Edit Screen)** — replaced the "Inline Validation" claim with a "Validation Feedback" bullet
   describing the real Snackbar-after-Save behavior; added the footer disclosure line; noted that the
   paste-suggestion banner's host check omits `m.youtube.com/`.
7. **§5.3 (Detail Screen)** — noted the "Same as created" literal string shown for the Updated field when
   a shortcut has never been edited.
8. **§5.7 (Permissions Screen)** — described both real sections ("Explicit Permissions: None" and
   "Implicit Permissions / Declarations" with 5 entries, including the previously-undocumented "Launcher
   visibility" entry) plus the intro card text.
9. **§5.8 (Channel Handles Screen)** — added the concrete 5-row fallback-behavior table and the "Good to
   know" notes (no connectivity check; how to open the channel page instead of `/live`).

## Why

An agent-assisted line-by-line comparison against the actual Dart source (all screens, the URL formatter,
the share-intent service, the backup service, the error types) and the Android manifest/Gradle files found
six factual inaccuracies and about nine missing behaviors in the document, which calls itself the
"authoritative" feature reference. This pass brings the document back in line with the real app so future
developers, auditors, and AI assistants can trust it.

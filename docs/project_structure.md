# Project Structure — SreerajP YouTube Shortcuts

This living document details the repository layout and layer responsibilities for SreerajP YouTube Shortcuts.

**Read first:** [../CLAUDE.md](../CLAUDE.md) · [architecture.md](architecture.md) for architectural rules and layer boundaries · [`docs/guidelines/guideline.md`](guidelines/guideline.md) §3 for the baseline layout every app follows.

## 2. Layer Responsibilities

| Directory | Holds | Must not |
|---|---|---|
| `lib/app/` | App widget, provider wiring, theme, lock gate | Contain business rules or storage code |
| `lib/core/config/` | `AppConfig` + `ConfigService` (fixed path per guideline §1) | Be moved or renamed |
| `lib/core/constants/` | Compile-time constants with no logic | Hold user-visible text |
| `lib/core/errors/` | The sealed `AppException` hierarchy | Throw raw `Exception` or strings |
| `lib/l10n/` | ARB strings, generated lookups, enum label extensions | Be edited by hand except `app_en.arb` and `model_labels.dart` |
| `lib/models/` | Immutable entities, enums, parse results | Hold UI copy, `BuildContext`, or storage details |
| `lib/repositories/` | Reading and writing `SharedPreferences` | Know about widgets |
| `lib/services/` | URL formatting, launching, backup, share intents, biometrics | Know `BuildContext`, navigation, or UI copy |
| `lib/state/` | `ChangeNotifier` stores the UI listens to | Import widget classes |
| `lib/screens/` | Full-page UI and user interaction | Parse URLs or touch `SharedPreferences` |
| `lib/widgets/` | Reusable presentational components and dialogs | Contain business or parsing logic |
| `test/` | Unit and widget tests mirroring `lib/` | — |

## 3. Test Layout

`test/` mirrors `lib/` so ownership is obvious:

```
test/
├── models/     # qr_payload_parser_test.dart
├── services/   # backup, privacy lock, youtube url formatter
├── state/      # shortcut store, privacy lock store
└── widget_test.dart
```
